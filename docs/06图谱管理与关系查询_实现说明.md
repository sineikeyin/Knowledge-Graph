## 使用流程

1. 启动 `npm start`，登录管理员账号，打开“图谱管理”。正式图只展示第五步审核发布的知识；空图时有明确引导。
2. 体验五类对象可选择“知识范围 → 虚构图谱演示”。演示覆盖地层、测井、井轨迹、地质模型和历史导向指令，同时包含井与井段节点。虚构坐标、模型和指令都有演示标识；不写入正式发布事实。
3. 在“实体与关系”中选择所属井或对象类型时，列表、图中心和详情即时联动；关键词输入后点击“应用筛选”。也可通过左侧资源树、“详情”、关联图节点或“关联图对象”下拉框切换对象。暂无可访问已发布知识的井显示空态，不保留其他井的图；“查看来源资料”进入数据资产，真实知识可下载固定版本原件。
4. 在“多跳路径”选择起终点、关系与最大跳数。默认双向遍历；按关系方向查询时只沿发布/计算边的方向行进。点击“将路径带入检索”可以回查同一组图谱对象的证据。
5. 在“空间邻近”体验演示数据，或在正式范围登记坐标。坐标必须有明确框架和同井来源资料；登记/修改需要该井及来源的导入权限。经纬度按 X=经度、Y=纬度输入；local 的单位为 m。
6. 在“相似井”选择目标和三类因素权重。候选井按钮保留原目标井与所选参考井，进入混合检索后显示相应图谱上下文。
7. 在“图算法”选择算法、关系范围及参数，提交后查看本机任务结果；历史任务只展示本人提交且目前仍有来源权限的记录。
8. 在“时序与版本”比较知识发布前后或恢复前后的版本。井深范围必须同时填写上下限，并明确 MD/TVD 及 KB/MSL/GL。时间范围限定版本生成时间。
9. 使用具有发布权限的账号创建快照。恢复时填写完整 `GS-…` 编号；恢复后可利用“恢复前自动备份”再次恢复，以撤销刚才的图谱切换。

## 计算与数据边界

- 正式图数据来自 `construction.facts` 中现行已发布事实；候选、待审和驳回知识不进入正式查询。部署升级会从已有发布记录补建历史图版本，不清空现有资料。
- 原始发布事实保持不变。同井和同基准井段内的关联是可重算的计算边，页面以虚线及“计算关系”区分，并保存计算理由。计算边不会作为新增审核事实写入知识库。
- 已发布知识缺少上下层位、构造、空间坐标、模型适用范围等字段时，详情明确列为“尚未提供”；不补造实际地质属性。五类实体都支持属性和来源查询，具体字段由固定本体及上游抽取结果决定。
- 井轨迹的井深、井斜与方位角不足以确定绝对位置。本次通过有来源的人工坐标登记提供实际空间查询，不猜测轨迹空间坐标。
- local 必须是同一米制框架。EPSG:4326 采用平均地球半径的球面近似水平距离，不处理高程、投影转换和大地测量精度要求。经纬度断层折线须先转换到一致米制框架后登记。
- 矩形空间范围对点进行坐标筛选，对断层折线使用包围盒相交候选筛选；半径判断仍计算到整条折线的最短距离。返回的 `index` 字段说明网格大小、占用网格与候选数。
- 相似井采用结构化语义匹配，未接入向量嵌入服务；曲线因素使用可比曲线均值，不宣称完成全曲线对齐。层位为集合 Jaccard；曲线均值为 `1 - min(1, abs(a-b)/max(abs(a),abs(b),1))`；工程因素为 `1 - min(1, abs(井斜均值差)/180)`。有效因素按用户权重归一化，缺失数据不冒充零分或完整匹配。
- 度中心度为去重无向邻居数除以 `N-1`；自环不计度。社区发现为确定性的异步标签传播，用于结构探索。图算法不产生生产导向指令。
- 图计算限制为 3,000 个实体与 12,000 条边；路径最多 20 条、30,000 次邻接探索，达到上限会标记未穷尽。社区迭代上限 50 次；每用户每项目保留最近 30 个算法任务。
- 每项目最多 2,000 条空间记录和 100 个图快照。本机计算任务与恢复在单次请求内完成，页面显示实际完成记录，不伪装外部后台队列。
- 快照只覆盖正式知识图的活动版本、派生名称索引和统计缓存；不会覆盖原始上传文件、治理/校核历史、本体版本、空间登记、用户或权限。恢复不是系统磁盘备份或外部数据库灾备。
- 带入检索的是对象、来源版本、路径或井上下文。现有规则面板仍使用其单独标识的演示输入；图谱知识不会静默替代实测值。图版本或权限变化会使旧上下文失效，需返回重新查询。
- 存储沿用私有 `.runtime/platform.json` 与 `.runtime/ingestion/files/`，外部图数据库、向量数据库和分布式空间索引仍需后续接入。离线预览使用浏览器独立存储，业务和正式本机服务互不同步。

## 权限和恢复一致性

查询、路径、空间候选、相似井、历史差异、算法结果和快照都在服务端依据当前项目、井、资料、对象与字段权限过滤。来源字段受限时不下发原文和图谱属性；关系任一端不可访问时，该关系也不返回。历史算法任务撤销来源权限后不再返回。

提交算法需要 `graph` 和 `run`；登记坐标需要 `graph`、`import` 和井/资料/对象的导入授权。创建与恢复快照需要 `graph`、`publish` 及快照全部来源的发布授权；恢复还检查当前图的全部来源。HTTP 变更和查询 POST 使用现有会话及 CSRF 校验。内部 `graph-model.js`、版本与原件存储不经静态 HTTP 公开。

知识发布与快照恢复使用同一个持久化提交串行队列。恢复检查调用方提交的 `expectedRevision`，恢复前自动备份，验证不存在悬空关系并重建名称索引及统计缓存；处理失败时由提交事务回滚内存状态。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/graph?projectId=p1&dataset=published` | 授权图、存储状态、版本、空间数据、快照、本人算法任务与能力。`dataset=demo` 为独立虚构演示。 |
| POST | `/api/graph/paths` | `projectId/dataset/start/end/relation/maxHops/directed`。 |
| POST | `/api/graph/spatial` | `projectId/dataset/targetId/crs/frame/radius`，可选完整 `bounds`。 |
| POST | `/api/graph/similar` | `projectId/dataset/targetWellId/weights`。 |
| POST | `/api/graph/algorithm` | `projectId/dataset/algorithm/relation/wellId/nodeId/iterations`。 |
| POST | `/api/graph/spatial-save` | `projectId/wellId/assetId/name/kind/crs/frame/x/y/source`；断层额外提供 `points`。修改提供 `id/expectedRevision`。 |
| POST | `/api/graph/history` | `projectId/beforeId/afterId`，可选井、时间、深度范围及基准。 |
| POST | `/api/graph/snapshot` | `projectId/name/expectedRevision`。 |
| POST | `/api/graph/restore` | `projectId/snapshotId/confirm/expectedRevision`；`confirm` 必须等于完整快照编号。 |
