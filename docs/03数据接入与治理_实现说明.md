# 03 数据接入与治理：第一批实现说明

本次实现从“文件名登记”升级到真实文件导入与治理。页面使用原有项目上下文、数据树与蓝色工作台布局，包含数据资产、接入任务、主数据映射、质量治理、连接器五个页签。

## 0.4.0 补充

第五部分开发已增加 LAS 2.x ASCII 文件接入、头段对照与知识抽取 / 人工校核 / 发布。导入LAS请选择“测井”，明确深度类型和参考基准。使用方式及限制以[05知识抽取与人工校核实现说明](05知识抽取与人工校核_实现说明.md)为准。下文保留0.2.x阶段的实施记录，当时的“仅CSV/JSON”和“尚未抽取发布”不再代表当前版本。

## 历史页面范围（0.2.2）

连接器页面只保留文件／CSV／JSON接入；导入向导和本机上传接口均限制为CSV或JSON文件。接入任务页只展示文件解析任务，已移除随钻实时接入区域。

数据资产点击筛选、重置和翻页时保留工作区滚动位置。第二批预置资料及其下载文件名已去掉演示前缀，已有运行库和离线浏览器数据会增量升级；来源栏继续说明虚构样例属性。升级不会改变资料ID、原件内容、摘要、版本链、质量结果或知识构建交接。用户上传的原始文件名不做修改。

## 预置演示记录（0.2.1）

本机启动时会为未改动的内置示例项目增量初始化演示记录，旧版本已有的空治理库也会自动补齐。离线HTML在自己的浏览器存储中独立执行同一初始化流程。

两个示例项目合计包含：

| 内容 | 数量与用途 |
| --- | --- |
| 演示资料与原件 | 17份，使用普通资料名称，来源栏标识虚构样例 |
| 接入解析任务 | 17条，其中15条完成、2条格式错误失败 |
| 主数据映射 | 20条，井、层位、岩性、区块各5条 |
| 资料版本 | 22个，包含5份分层资料修正前后的父子版本 |
| 质量校验 | 20次，当前资料中通过、警告、阻断各5份，另有2份解析失败资料 |
| 待知识构建交接 | 5条，固定合格版本和对应质量校验编号 |

默认“鄂尔多斯示例工区”可看到10条接入任务、12条映射和12次历史校验；“松辽示例工区”可看到7条任务、8条映射和8次历史校验。资产目录默认筛选当前井，其他井可从左侧树或井筛选切换。

演示数据由正常解析器、归一规则和质量引擎生成，通过状态不是写死的展示结果。分层样例展示归一、修正、复检与固定版本交接；曲线样例通过明确的演示阈值产生警告；问题分层展示阻断；错误CSV展示解析失败和原因。

初始化由版本标记控制，服务重启和离线刷新不会重复追加。后续上传资料、已有用户、授权、原件、版本和校验记录均保留。演示映射及其修订号与用户映射分开，编辑演示映射不会使用户资料失效，用户资料也不会自动采用演示别名。只读账号等原有授权限制继续生效。

真实原件仍留在私有运行目录；GitHub提交的是可复现这些演示记录的初始化代码，不包含本机账号凭据和运行数据库。可通过“记录来源”筛选系统演示或用户资料。离线演示的摘要只用于样例标识，本机原件使用实际SHA-256。

手动初始化命令为`npm run demo:init`，需要先停止平台服务；通常直接重启本机服务即可。初始化脚本检测到运行中的平台时会退出，避免覆盖其尚未落盘的数据。

| M2-F6 血缘与版本 | 不变原件、SHA-256、版本父子关系、解析器及映射快照、历次校验、固定版本交接 |

## 启动与验收

在项目目录运行 `npm start`，打开终端输出地址。使用已分配账号登录，进入“数据接入”。服务已经运行时，更新代码后需重启该服务并重新登录。

以管理员和示例项目“鄂尔多斯示例工区”的 JH-01 为例：

1. 点击“导入资料”，选择 `docs/samples/01_合格地层分层.csv`，资料类型为地层。
2. 检查自动映射。默认值只用于未映射字段，深度单位、深度类型和参考基准需按原件确认。
3. 预览后确认上传。正式原件由服务保存，解析完成后进入详情。
4. 点击“运行质量校验”，基础规则自动执行；曲线阈值等留空时为不适用。
5. 质量通过后点击“构建知识”，确认固定的数据版本和校验记录，在知识构建清单回查输入。
6. 在解析预览中修正数据；修正会产生新版本，必须重新校验。旧版本、原件和旧交接仍保留。

额外样例：

- `02_质量问题地层分层.csv`：底深倒置、未知层位、归属井不符、未知单位和缺少基准。用于验证问题定位与交接阻断。
- `03_需归一地层分层.csv`：在 JH-01 新增井别名“示例一号井 → JH-01”和层位别名“长8一 → 长 8₁”，再重新标准化、校验。
- `04_测井曲线.json`：使用“测井”类型。可设置曲线最大值81或相邻变化阈值1，验证警告、阈值记录及人工确认。

样例均为虚构记录。示例KB基准、地层命名及质量阈值不能直接当作现场标准。

## 数据口径与限制

- 当前仅接受CSV或JSON文件；文件扩展名不区分大小写。
- 单文件最多5 MB，最多5000条记录、128列、每单元格4096字符。此版本定位于本机小规模治理。
- CSV为逗号分隔，支持BOM、引号转义、引号内换行及原始物理行号；重复/空表头和列数不一致会失败。
- JSON支持对象数组或 `{ "records": [...] }`，字段只支持一层标量。
- 支持显式选择UTF-8或GB18030编码。编码错误需重新上传；失败任务可以重试。
- 深度单位支持m/米、ft/英尺；标准深度统一为m，保留原输入与单位。曲线值单位不会自动推断或换算。
- MD和TVD分别保留，不进行相互换算；参考基准必须明确。资料合格不代表不同资料之间已具备可比性。
- 无厚度值时可按同深度类型及参考基准的底深减顶深推导。非法厚度不会被推导结果掩盖。
- 地层检查区间、重复和重叠；测井/轨迹检查深度顺序及可选采样间距；测井可选范围/突变阈值必须结合曲线单位配置。
- 更改主数据映射后，相关当前版本标为待重新标准化。旧校验保留，但不能据此交接新数据。
- 修正保存标准化输入副本，不覆盖原件；重新上传原件也会产生新资料版本。
- 重复文件在相同项目/井/类型及可授权范围内去重；不会自动覆盖当前版本。
- 本机元数据仍使用JSON文件。多用户并发、大规模数据和生产部署需要数据库及持久化任务队列。

## 状态与交接

处理状态包括待解析、解析中、解析失败、待校验、处理完成、待重新标准化。质量状态独立为未校验、通过、警告、阻断。

知识构建交接固定资产版本ID、质量运行ID和记录数。服务端拒绝未校验、映射已过期或有阻断问题的版本；存在警告时要求显式确认。同一资产版本重复提交返回已有交接，避免重复任务。

不同深度基准下的数据虽然可以分别完成治理，后续对比仍必须验证深度类型和参考基准，不能因质量通过就认定可比较。

## 权限与存储

- 浏览需要数据目录权限、项目成员井范围及对象/文档查看权限。
- 上传、重试、映射、修正和校验需要导入权限及相应井/对象/文档的导入授权。
- 提交知识构建还需要知识构建模块权限。已有角色和项目授权不会被自动扩大；工程师若需交接，由管理员在用户权限中配置角色。
- 原件可能含受限字段，无法可靠脱敏时，服务端拒绝原件、解析、质量和血缘内容访问，仅返回可见元信息。直接访问文件接口也不能绕过。
- 元数据在 `.runtime/platform.json`，原件在 `.runtime/ingestion/files/`，使用服务端随机存储名；Git忽略整个`.runtime`。
- 文件通过鉴权路由下载，原文件名不作为磁盘路径；静态服务不会公开运行目录。
- 上传与解析独立于HTTP请求，不持有原有全局请求队列；元数据短事务串行提交并原子替换文件。
- 启动时将中断任务标为失败并允许重试；超过24小时且未被任何资料版本引用的原件文件会清理。
- 离线HTML只提供虚构样例治理。真实原件、真实权限隔离和本机持久化均使用本机服务。

## 主要接口

所有本机接口使用现有登录Cookie；写操作同时要求CSRF请求头。JSON元数据接口仍维持64 KB上限。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/ingestion?projectId=...` | 授权资产、任务、别名、交接及规则 |
| GET | `/api/ingestion/assets/:assetId` | 元信息与可授权读取的版本详情 |
| POST | `/api/ingestion/upload` | 二进制原件；参数含项目、井、类型、文件名、编码及可选目标资产/期望版本 |
| GET | `/api/ingestion/files/:versionId` | 鉴权原件下载 |
| POST | `/api/ingestion/alias` | 确认或编辑主数据映射 |
| POST | `/api/ingestion/standardize` | 字段映射及重新标准化 |
| POST | `/api/ingestion/correct` | 指定行与字段修正，生成新版本 |
| POST | `/api/ingestion/validate` | 固定规则版本与阈值执行质量校验 |
| POST | `/api/ingestion/retry` | 为失败版本创建新解析尝试 |
| POST | `/api/ingestion/handoff` | 合格资料固定版本交接 |

上传使用`application/octet-stream`；字段配置放在有长度限制的`X-Import-Config`头中。新原件版本要求携带`assetId`和`expectedVersionId`；其他资料变更携带`assetId`和`versionId`，过期操作返回409。
