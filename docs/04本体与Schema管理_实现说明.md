# 04 本体与 Schema 管理

依据 `docs/页面搭建步骤.html` 第四步 M3 的六项功能实现。入口为工作台顶部“本体管理”，版本为 0.3.1。

## 版本操作与界面调整（0.3.1）

- 草稿无修改时显示“已保存”，“保存草稿”置灰；有修改时显示“有未保存修改”，同时提供“放弃修改”和可用的“保存草稿”。保存不增加版本号。
- 待审批和已批准版本的主操作区只显示“查看结构”；审批、退回和发布仍在“版本与审批”页签。
- 已发布版本显示“查看结构”和“基于此版本修改”。后者创建下一版草稿，提示原版保持不变。
- 草稿的复制入口移到“版本与审批 → 更多操作 → 复制为新草稿”，主操作区不再显示“复制为新版本”。
- 当前版本下拉框使用明确高度、文字行高及箭头留白，避免“请选择版本”和版本名称被上下裁切。
- 两个模板卡片的类型标签均保持紧凑高度，不随卡片空白区域拉伸。
- 点击画布类型或关系不出现黑色默认焦点框；仍保留蓝色选中效果和键盘焦点提示。

## 从建模到知识构建的验收路径

1. 在项目目录运行 `npm start`，登录 `admin`（初始开发密码 `GeoDemo!2026`），进入“本体管理”。
2. 点击“新建本体”或“模板库”，预览并使用“地质导向完整模板”。
3. 在建模页选择“井段”，查看字段、单位及 `bottom ≥ top` 约束。编辑一个字段后应用到草稿，再“保存草稿”。
4. 从左侧“新对象类型”拖到画布，定义名称及字段；使用“点击连线”，依次选择起点和终点，填写关系标识、名称和基数。
5. 在“术语与同义词”增加一个别名；在“数据源映射”点击样例预览。可选择预置的 `JH-01_分层归一与版本.csv`，加载标准数据及历史版本。
6. 在“业务动作”核查历史指令样本。将 `interval` 改为不存在的井段，重新校验，应提示关联失败。
7. 保存并“校验 Schema”。在“版本与审批”送审、填写意见并批准，查看影响、勾选确认并发布。管理员可完成整条示例流程；非管理员不能审批本人送审版本。
8. 进入“知识构建”，为待构建资料选择已发布本体并点击“固定版本”。资料版本、本体版本、选择人及时间会一起持久化。
9. 刷新或重启服务后，重新登录，检查本体、审批历史与固定版本选择仍在。
10. 已发布版本不能编辑；点击“基于此版本修改”后进入下一版草稿，不会自动改变原有资料绑定。草稿的另存方案入口位于“版本与审批 → 更多操作”。

尚无本体的项目展示模板入口；无权限、加载失败、空记录、校验失败和并发版本冲突均有提示。未保存草稿在刷新/退出页面前会提醒，切换本体版本需先保存或放弃修改。

## 权限与数据存储

新增权限 `ontology-edit`（编辑）、`ontology-review`（审批）及 `ontology-publish`（发布），模块查看仍使用 `ontology`。知识构建的已发布版本列表与选择使用 `construction` 权限，并再次检查资料访问和字段限制。

首次升级对内置角色增补本模块权限：管理员具有全部权限；项目管理员可编辑和发布；工程师可编辑；专家可查看和审批。新权限的迁移只执行一次，之后手动撤销的权限不会被重启恢复。项目成员的权限以项目角色为准；只读用户默认不获得本体权限。管理员可在现有用户权限页面调整角色。

本机数据保存在原有 `.runtime/platform.json` 的 `db.ontology` 下，包含本体版本、审批历史、发布定义影响与构建绑定；沿用现有认证、CSRF、串行事务、持久化和审计。使用 revision 检查避免多人操作覆盖。运行数据不纳入 Git。

离线 `首页预览.html` 同样包含建模、校验、审批发布及版本选择，在浏览器存储中保存独立示例数据。离线数据与本机服务不互相同步。

## 接口

- `GET /api/ontology?projectId=…`：当前项目本体版本和编辑/审批/发布能力。
- `GET /api/ontology/impact?projectId=…&versionId=…`：与最近发布版本比较的影响。
- `GET /api/ontology/published?projectId=…`：知识构建可选已发布版本与可访问资料的绑定。
- `POST /api/ontology/create`：从模板或已有版本建立新草稿。
- `POST /api/ontology/save`：保存草稿，需当前 `expectedRevision`。
- `POST /api/ontology/submit`、`approve`、`reject`、`publish`：状态转换及审批记录。
- `POST /api/ontology/bind`：固定交接资料版本与已发布本体版本，需绑定的 `expectedRevision`（首次为 0）。

除新建外，本体修改请求包含 `projectId`、`versionId`、`expectedRevision`；审批提供 `note`；发布提供 `confirmImpact: true`。Schema 内容可在草稿阶段暂存逻辑错误，但送审及发布必须通过服务端校验。畸形结构请求直接拒绝。

## 实现范围

本模块提供平台内部 JSON Schema 定义及确定性校验，不实现 OWL/RDF 推理或外部本体格式导入。字段映射针对 03 模块治理后的标准字段，不包含任意脚本执行或大模型抽取。时间检查要求含时区的时间文本，不自动猜测时区。

业务动作目前定义并校验写入前输入，不实际写入知识图谱或下发现场指令。历史指令对象关联使用页面标明的虚构样本上下文。

图数据库、全文/向量索引尚未接入，发布影响页据实显示索引状态，不伪造重建结果；现有厚度差规则独立运行，字段变更影响需人工核对。05 知识抽取与人工校核将在后续实现，本次只接通其“选择已发布本体版本”的输入。
